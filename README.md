# jenova_lab

A small Go CLI for spinning up a local chain of Dockerized HTTP services, useful
for testing and demoing service-to-service call chains, downstream failures,
and tracing/logging setups.

Running `lab up` generates a `docker-compose` file with N chained services
(`service-1 -> service-2 -> ... -> service-N`) and starts them with Docker
Compose. Each service exposes a `/health` endpoint and a `/work` endpoint;
calling `/work` on a service calls `/work` on its downstream service (if any)
and nests the response, so a request to `service-1` triggers a call through
the entire chain down to the last service.

## Requirements

- Go 1.26+
- Docker with the Compose plugin (`docker compose`)

## Build

```sh
go build -o bin/lab ./cmd/lab
```

## Usage

```
lab up [--services N]
lab status
lab down
```

- `lab up [--services N]` — generates `compose.generated.yaml` for a chain of
  `N` services (default `3`) and starts them via `docker compose up --build -d`.
- `lab status` — shows running containers (`docker compose ps`).
- `lab down` — stops and removes the containers (`docker compose down`).

### Example

```sh
lab up --services 4
```

Starts `service-1` through `service-4`, each built from
[service/Dockerfile](service/Dockerfile) and published on host ports
`8001`-`8004` (container port `8080`). `service-1` is downstream of nothing
calling it; `service-4` is the leaf with no `DOWNSTREAM_URL` set.

Query the chain:

```sh
curl http://localhost:8001/work
```

This returns a nested JSON response as the request propagates through each
service in the chain down to the leaf:

```json
{
  "service": "service-1",
  "status": "ok",
  "downstream": {
    "service": "service-2",
    "status": "ok",
    "downstream": {
      "service": "service-3",
      "status": "ok",
      "downstream": {
        "service": "service-4",
        "status": "ok"
      }
    }
  }
}
```

If a downstream service is unreachable or returns an error, the calling
service reports `"status": "error"` along with an `"error"` message instead
of propagating a downstream chain.

## Project layout

- [cmd/lab](cmd/lab) — CLI entry point; generates the compose file and drives
  `docker compose`.
- [service](service) — the chained HTTP service (`/health`, `/work`) and its
  [Dockerfile](service/Dockerfile).
- `compose.generated.yaml` — generated by `lab up`; not committed (see
  [.gitignore](.gitignore)).

## Service configuration

Each service instance reads its configuration from environment variables,
set automatically in the generated compose file:

| Variable          | Description                                              |
|-------------------|------------------------------------------------------------|
| `SERVICE_NAME`    | Name reported in responses and logs.                     |
| `PORT`            | Port the service listens on inside the container.        |
| `DOWNSTREAM_URL`  | Base URL of the next service in the chain (unset for the last/leaf service). |
