# jenova_lab

A small Go CLI for spinning up a local chain of Dockerized HTTP services, useful
for testing and demoing service-to-service call chains, downstream failures,
and tracing/logging setups.


## Requirements

- Go 1.26+
- Docker with the Compose plugin (`docker compose`)

## Build

```sh
make build                       # or: go build -o bin/lab ./cmd/lab
make run ARGS="up --services 4"  # build, then run bin/lab with those args
```

## Usage

All commands operate on `compose.generated.yaml` in the current directory, so
run `lab` from the repo root and run `lab up` first.

| Command | Description |
|---------|-------------|
| `lab up [--services N]` | Generate the compose file for a chain of `N` services (default `3`) and start them (`--build -d`). Service `i` is published on host port `800i`; the last service is the leaf. |
| `lab status` | Show running containers (`docker compose ps`). |
| `lab down` | Stop and remove the containers. |
| `lab kill <service>` | Kill one service's container, leaving the rest running — simulates a hard downstream outage. |
| `lab latency <service> <duration>` | Inject latency into one service via its `/fault/latency` endpoint. Go duration string (`500ms`, `1s`); `0s` clears it. |
| `lab reset` | Force-recreate every container: restarts killed services and clears injected latency. |

Injected latency lives in memory in the target service, so it persists until the
container is recreated. A caller gives up on its downstream after 2s, so latency
at or above that becomes a timeout error rather than a slow success.


```json
{
  "service": "service-1",
  "status": "ok",
  "downstream": {
    "service": "service-2",
    "status": "ok",
    "downstream": { "service": "service-3", "status": "ok" }
  }
}
```

If a downstream is unreachable or errors, the caller reports
`"status": "error"` with an `"error"` message instead of a nested chain.

## HTTP endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/health` | GET | Liveness check; returns service name and `"status": "ok"`. |
| `/work` | GET | Does the work and calls the downstream service, nesting its response. |
| `/fault/latency` | POST | Sets injected latency from the `duration` query param. Used by `lab latency`. |

## Project layout

- [cmd/lab](cmd/lab) — CLI entry point; generates the compose file and drives
  `docker compose`.
- [service](service) — the chained HTTP service, its
  [fault handlers](service/faults.go), and its [Dockerfile](service/Dockerfile).
- `compose.generated.yaml` — generated by `lab up`; not committed.

## Service configuration

Set automatically in the generated compose file:

| Variable | Description |
|----------|-------------|
| `SERVICE_NAME` | Name reported in responses and logs. |
| `PORT` | Port the service listens on inside the container. |
| `DOWNSTREAM_URL` | Base URL of the next service (unset for the leaf). |
